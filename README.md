# 📚 Bookshelf API

Учебный проект курса «Современный Express»: **книжная полка** — REST API на Express 5 с базой SQLite и простым фронтендом, который отдаётся тем же сервером.

Можно добавлять книги, менять их статус («хочу прочитать» → «читаю» → «прочитал»), редактировать и удалять.

> **Демо:** [Деплой на Render](https://express-q2bo.onrender.com/)

На бесплатном тарифе сервис «засыпает» через 15 минут простоя, первый запрос после паузы занимает около минуты.

## Что внутри

| Слой | Технологии |
|---|---|
| Сервер | Node.js 24, Express 5, ES-модули |
| База данных | SQLite через встроенный `node:sqlite` (без установки драйверов) |
| Фронтенд | HTML + CSS + JavaScript-модули, без фреймворков и сборщика |
| Инструменты | Biome (линтер и форматтер), nodemon, коллекция запросов Bruno |

Что важно знать:

- Фронтенд лежит в `public/` и отдаётся самим Express — отдельного фронтенд-сервера нет, поэтому запросы идут на тот же адрес (`/books`) и **CORS не нужен**.
- `node:sqlite` в Node 24 помечен как экспериментальный — при запуске может появиться предупреждение `ExperimentalWarning`. Это нормально.

## Быстрый старт

Нужен **Node.js 24 или новее**. Проверьте версию:

```bash
node -v
```

> ⚠️ **На более старых версиях сервис не заработает.** На Node 22.14.0 каждый запрос к базе падает с ошибкой `statement has been finalized` — это баг `node:sqlite`, исправленный в более поздних релизах.

Дальше:

```bash
git clone https://github.com/agkondakov91/ed_TRPO_Express.git
cd ed_TRPO_Express
npm install
npm run dev
```

Откройте <http://localhost:3000> — это страница книжной полки.

Файл базы `bookshelf.db` создастся автоматически при первом запуске. **Начальных данных нет**: полка сначала пустая, книги добавляются через форму или API.

## Переменные окружения

Все переменные необязательны. Если не заданы — используются значения по умолчанию.

| Переменная | По умолчанию | Для чего |
|---|---|---|
| `PORT` | `3000` | Порт сервера. На хостинге его назначает платформа |
| `DB_PATH` | `bookshelf.db` | Путь к файлу базы SQLite |

Пример запуска на другом порту:

```bash
PORT=4000 npm start
```

> ℹ️ Файл `.env` Node сам **не читает**. Чтобы подгружать его, запускайте `node --env-file=.env server.js`. Файл `.env` добавлен в `.gitignore`.

> ⚠️ **macOS:** порты 5000 и 7000 занимает служба AirPlay Receiver. Для проверок берите 3000, 4000 или 8080.

## API

Базовый адрес локально: `http://localhost:3000`. Тела запросов и ответов — JSON.

### Модель книги

```json
{
  "id": 1,
  "title": "Дюна",
  "author": "Фрэнк Герберт",
  "year": 1965,
  "status": "прочитал"
}
```

| Поле | Тип | Обязательное | Примечание |
|---|---|---|---|
| `id` | число | — | Назначается базой |
| `title` | строка | да | Название |
| `author` | строка | да | Автор |
| `year` | число | нет | Если не передан — сохраняется `0` |
| `status` | строка | нет | По умолчанию `хочу прочитать`. При обновлении, если не передан, остаётся прежним |

### Маршруты

| Метод | Путь | Что делает | Успешный ответ |
|---|---|---|---|
| GET | `/books` | Список всех книг | `200` + массив |
| GET | `/books/:id` | Одна книга | `200` + объект |
| POST | `/books` | Создать книгу | `201` + созданная книга |
| PUT | `/books/:id` | Обновить книгу | `200` + обновлённая книга |
| DELETE | `/books/:id` | Удалить книгу | `204` без тела |
| GET | `/health` | Проверка «сервис жив» | `200` + `{"status":"ok"}` |

### Ошибки

| Код | Когда | Тело ответа |
|---|---|---|
| `400` | Нет `title` или `author` | `Нужно указать title и author` |
| `400` | `year` передан не числом | `Поле year должно быть числом` |
| `404` | Книги с таким `id` нет | `Книга не найдена` |
| `500` | Непредвиденная ошибка на сервере | `{"status":"error","message":"Что-то пошло не так на сервере"}` |

### Примеры

Создать книгу:

```bash
curl -X POST http://localhost:3000/books \
  -H "Content-Type: application/json" \
  -d '{"title":"Чистый код","author":"Роберт Мартин","year":2008}'
```

Изменить статус:

```bash
curl -X PUT http://localhost:3000/books/1 \
  -H "Content-Type: application/json" \
  -d '{"title":"Чистый код","author":"Роберт Мартин","year":2008,"status":"читаю"}'
```

> 💡 `PUT` заменяет книгу целиком: `title` и `author` обязательны и в обновлении.

### Учебные маршруты

В `server.js` остались маршруты с занятий по middleware и обработке ошибок:

- `/admin` — демонстрация собственного middleware (пишет в консоль о заходе);
- `/crash-test` и `/sync-crash` — **намеренно ломаются**, чтобы показать, как работает `handleErrors`.

Перед «боевой» публикацией проекта их стоит убрать.

    ├── style.css          # подключает файлы из css/
    ├── css/
    │   ├── tokens.css     # цвета, отступы, шрифты (CSS-переменные)
    │   ├── base.css
    │   ├── layout.css
    │   ├── forms.css
    │   ├── book-card.css
    │   ├── dialog.css
    │   └── toast.css
    └── js/
        ├── main.js            # точка входа, связывает всё вместе
        ├── api.js             # обёртка над fetch
        ├── errors.js          # класс ApiError

## Скрипты

| Команда | Что делает |
|---|---|
| `npm start` | Обычный запуск: `node server.js` |
| `npm run dev` | Запуск с автоперезапуском через nodemon |
| `npm run check` | Проверка и автоисправление кода через Biome |
| `npm run rewrite` | То же, но с «небезопасными» правками (`--unsafe`) — смотрите diff перед коммитом |

## Как устроен фронтенд

Несколько решений, на которые стоит обратить внимание:

- **ES-модули.** Каждый файл в `js/` отвечает за одно дело, `main.js` их собирает.
- **Никакого `innerHTML`.** Карточки создаются через `createElement` и `textContent`, поэтому текст книги не может выполниться как код (защита от XSS).
- **Одна точка для запросов.** Все обращения к серверу идут через `api.js`; при ошибке он бросает `ApiError`, а интерфейс показывает уведомление.
- **Нативный `<dialog>`** для редактирования — без библиотек.
- **Цвет статуса** задаётся атрибутом `data-status` и CSS, без логики в JavaScript.
- **CSS на переменных.** Все цвета и размеры живут в `tokens.css`.

## Деплой

Проект рассчитан на платформы вроде Render и Railway.

| Параметр | Значение |
|---|---|
| Build command | `npm install` |
| Start command | `npm start` |
| Версия Node | берётся из `engines` (`24.x`) |
| Health check path | `/health` |
| Ветка для автодеплоя | `main` |

Что учесть:

- Порт платформа передаёт через `PORT` — менять код не нужно, он уже читает эту переменную.
- На бесплатном тарифе Render **файловая система эфемерная**: файл SQLite сбрасывается при перезапуске и новом деплое. Для учебного стенда это нормально, для настоящих данных нужна постоянная база.
- Фронтенд и API на одном домене, поэтому настройка CORS не требуется.

## Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| `statement has been finalized` на каждый запрос | Старая версия Node (например, 22.14.0) | Обновить Node до 24.x |
| Сервер напечатал «запущен» и сразу завершился | Порт занят (на macOS — 5000 и 7000) | Взять другой порт: `PORT=4000 npm start` |
| `EADDRINUSE` | Порт уже занят другим процессом | Остановить старый процесс или сменить `PORT` |
| `node: .env: not found` | Запуск с `--env-file`, а файла нет | Создать `.env` или запускать без флага |
| Ошибка при добавлении книги без года | Поле `year` передано как `null` или строка | Не передавать `year` вообще или передавать число |
| Первое открытие демо-ссылки долго грузится | Бесплатный сервис «просыпается» | Подождать около минуты |

## Проверка качества кода

```bash
npx biome check .
```

Biome форматирует код (табы, одинарные кавычки, точки с запятой) и ищет типичные ошибки. Рекомендуется запускать перед каждым коммитом.
